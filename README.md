# Student Management System (CRUD)

เว็บแอปพลิเคชันตัวอย่างสำหรับจัดการข้อมูลนักศึกษา พัฒนาด้วย Next.js, React, TypeScript และ Prisma พร้อมระบบสมัครสมาชิกและเข้าสู่ระบบ

## เทคโนโลยีที่ใช้

- **Next.js 16** — Framework สำหรับพัฒนาเว็บแอปพลิเคชัน
- **React 19** — สร้างส่วนติดต่อผู้ใช้
- **TypeScript** — เพิ่มชนิดข้อมูลให้โค้ด
- **Prisma 7** — ORM สำหรับติดต่อฐานข้อมูล
- **SQLite** — ฐานข้อมูลสำหรับการพัฒนา
- **NextAuth.js** — ระบบยืนยันตัวตนและจัดการ Session
- **Zod** — ตรวจสอบความถูกต้องของข้อมูลฟอร์ม
- **Tailwind CSS 4** — จัดรูปแบบหน้าเว็บ
- **bcryptjs** — เข้ารหัสรหัสผ่านก่อนบันทึกลงฐานข้อมูล

## ความสามารถหลัก

- เพิ่ม แสดง แก้ไข และลบข้อมูลนักศึกษา (CRUD)
- จัดเก็บข้อมูลนักศึกษา ได้แก่ รหัสนักศึกษา ชื่อ-นามสกุล อีเมล สาขาวิชา และชั้นปี
- ตรวจสอบข้อมูลก่อนบันทึกด้วย Zod
- ป้องกันรหัสนักศึกษาซ้ำด้วยเงื่อนไข `studentCode` ที่ไม่ซ้ำกันในฐานข้อมูล
- สมัครสมาชิกและเข้าสู่ระบบด้วยอีเมลและรหัสผ่าน
- รองรับการเข้าสู่ระบบด้วย GitHub เมื่อกำหนดค่า OAuth
- แบ่งบทบาทผู้ใช้งาน เช่น `ADMIN`, `STAFF` และ `USER`
- มีหน้า Dashboard, Admin, Blogs และตัวอย่าง Skeleton / Loading / Error / Not Found

## สิ่งที่ต้องติดตั้งก่อนเริ่มใช้งาน

- Node.js เวอร์ชันที่รองรับ Next.js 16
- npm
- Visual Studio Code (แนะนำ)
- Git (ถ้าต้องการจัดการเวอร์ชันโค้ด)

ตรวจสอบเวอร์ชัน Node.js และ npm ได้ด้วยคำสั่ง

```bash
node -v

```

## วิธีติดตั้งและรันโปรเจกต์

### 1. ดาวน์โหลดโปรเจกต์และเข้าโฟลเดอร์

```bash
cd "my crud"
```

### 2. ติดตั้งแพ็กเกจ

```bash
npm install
```

### 3. ตั้งค่าไฟล์ Environment

สร้างไฟล์ `.env` ที่โฟลเดอร์หลักของโปรเจกต์ และกำหนดค่าตัวอย่างดังนี้

```env
DATABASE_URL="file:./dev.db"
AUTH_SECRET="ใส่ค่า secret แบบสุ่มที่คาดเดายาก"
AUTH_GITHUB_ID=""
AUTH_GITHUB_SECRET=""
```

สร้างค่า `AUTH_SECRET` ได้ด้วยคำสั่ง

```bash
npx auth secret
```

หากไม่ใช้ GitHub Login สามารถเว้น `AUTH_GITHUB_ID` และ `AUTH_GITHUB_SECRET` ว่างไว้ได้ ทั้งนี้ห้ามนำค่า Secret จริงขึ้น GitHub หรือแชร์สู่สาธารณะ

### 4. เตรียมฐานข้อมูลและ Prisma Client

```bash
npx prisma migrate dev
npx prisma generate
```

โปรเจกต์นี้ใช้ SQLite โดยค่า `DATABASE_URL` ตัวอย่างชี้ไปที่ `dev.db` ตามการตั้งค่าในโปรเจกต์ หากคำสั่ง Migration แจ้งว่ามี Migration ที่ใช้แล้วหรือฐานข้อมูลไม่ตรงกับ Schema ให้อ่านข้อความแจ้งเตือนก่อนดำเนินการ และอย่าลบฐานข้อมูลหากมีข้อมูลที่ต้องการเก็บไว้

### 5. เปิดเซิร์ฟเวอร์สำหรับพัฒนา

```bash
npm run dev
```

จากนั้นเปิดเบราว์เซอร์ที่

http://localhost:3000

หยุดเซิร์ฟเวอร์ด้วย `Ctrl + C`

## โครงสร้างไฟล์ที่สำคัญ

```text
my crud/
├── app/
│   ├── admin/              # หน้าผู้ดูแลระบบ
│   ├── api/auth/           # Route สำหรับ NextAuth
│   ├── blogs/              # หน้า Blog และสถานะต่าง ๆ
│   ├── dashboard/          # Dashboard
│   ├── login/              # หน้าเข้าสู่ระบบ
│   ├── signup/             # หน้าสมัครสมาชิก
│   ├── students/           # ฟังก์ชัน CRUD นักศึกษา
│   ├── auth.ts             # ตั้งค่าระบบยืนยันตัวตน
│   ├── generated/prisma/   # Prisma Client ที่สร้างขึ้น
│   └── lib/prisma.ts       # การเชื่อมต่อฐานข้อมูล
├── prisma/
│   ├── migrations/         # ประวัติการเปลี่ยนแปลงฐานข้อมูล
│   └── schema.prisma       # โครงสร้างข้อมูล
├── prisma.config.ts        # ตั้งค่า Prisma
├── package.json            # Dependencies และ Scripts
└── README.md               # คู่มือโปรเจกต์
```

## โครงสร้างข้อมูล

### Student

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | รหัสภายในของรายการ (สร้างอัตโนมัติ) |
| `studentCode` | รหัสนักศึกษา ต้องไม่ซ้ำกัน |
| `name` | ชื่อ-นามสกุล |
| `email` | อีเมล (ไม่บังคับ) |
| `major` | สาขาวิชา |
| `year` | ชั้นปี |
| `status` | สถานะของนักศึกษา มีค่าเริ่มต้นเป็น `true` |
| `createdAt` | วันที่สร้างข้อมูล |
| `updatedAt` | วันที่แก้ไขข้อมูลล่าสุด |

### User

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | รหัสผู้ใช้ |
| `name` | ชื่อผู้ใช้ |
| `email` | อีเมล ใช้ระบุบัญชีและต้องไม่ซ้ำ |
| `passwordHash` | รหัสผ่านที่ผ่านการ Hash แล้ว |
| `role` | บทบาท `ADMIN`, `STAFF` หรือ `USER` |
| `createdAt` / `updatedAt` | วันเวลาสร้างและแก้ไขข้อมูล |

## หมายเหตุด้านความปลอดภัย

- อย่าเผยแพร่ไฟล์ `.env` หรือค่า `AUTH_SECRET` และ GitHub OAuth Secret
- อย่าเก็บรหัสผ่านแบบข้อความธรรมดา โปรเจกต์นี้ใช้ `bcryptjs` เพื่อ Hash รหัสผ่าน
- ก่อนนำไปใช้งานจริง ควรตรวจสอบสิทธิ์การเข้าถึงทุกหน้าและทุก Server Action ที่แก้ไขข้อมูล
- ควรสำรองไฟล์ฐานข้อมูล SQLite ก่อนปรับเปลี่ยน Schema หรือ Migration
